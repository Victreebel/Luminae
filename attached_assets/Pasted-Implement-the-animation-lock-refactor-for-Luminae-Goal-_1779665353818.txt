Implement the animation-lock refactor for Luminae.

Goal:
Animations should communicate board events without unnecessarily blocking player planning.

Required changes:
1. Separate true turn ownership from animation/core-action availability.
   - Do not make `isMyTurn` false just because the “Your Turn” announcement is playing.
   - Keep server/auth turn ownership separate from UI lock reasons.

2. Introduce separate derived lock concepts:
   - `canCoreAct`: true only when it is the local player’s server-authoritative turn and no core action lock is active.
   - `canPlan`: true unless a true planning lock is active.
   - Suggested lock reasons:
     - `coreActionLockedReason`: `"turnAnnouncement" | "submitted" | "resolving" | null`
     - `planningLockedReason`: `"summonCutscene" | "boardMutating" | null`

3. `turnAnnouncement` should only block core submissions:
   - Block forge submit, harvest submit, reserve submit, return-crystals submit, and end-turn.
   - Allow crystal pre-selection, Plan: Forge, Plan: Reserve, card inspection, and other planning UI.

4. `summonGateActive` should remain the only hard cinematic lock.
   - During summon cutscene, block both core actions and planning.
   - If `localSummonSkipped` is true, restore planning if the board state is stable.
   - Core actions should remain blocked until summon resolution is complete.

5. Restore Luminary affinity toggle interactivity.
   - `toggle_luminary_affinity` is intended as a non-turn action.
   - Reintroduce a UI-side `canToggleLuminaryAffinity` guard.
   - It should be allowed when no hard summon gate is active, or when the local player has skipped the summon cutscene.
   - Do not accidentally tie it to `canCoreAct`.

6. Add or preserve clear UX messaging:
   - During turn banner, show that it is the player’s turn but core submission is briefly paused.
   - Planning controls should remain visibly usable.
   - Disabled core buttons should indicate the reason, e.g. “Available after turn banner.”

7. Add an action feed/ribbon if feasible without large layout disruption:
   - Show concise events like:
     - “Mira harvested: Flare + Continuum + Radiance”
     - “Jon forged: Photosynthetic Wick”
     - “Ari reserved a hidden Tier II artifact”
     - “Luminary awakened: [Name]”
   - Do not make the feed block planning.

Constraints:
- Do not change game balance, card data, scoring, artifact effects, costs, Luminary rules, Blueprint rules, or tutorial order.
- Keep this as a UI/interaction-lock refactor only.
- Prefer derived selectors/helpers over scattered boolean logic.
- After implementation, audit all forge, harvest, reserve, return-crystals, end-turn, planning, and Luminary toggle call sites for the correct guard.
