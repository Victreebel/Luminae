# LUMINAE_SYSTEM_GRAMMAR_V0.1.md

## Purpose

This document defines the core design grammar for **Luminae**. It is system-level canon for future work on Affinities, Artifacts, Luminaries, Blueprints, UI language, color identity, and tutorial explanations.

This document **does not replace the current Luminary roster**. Existing Luminaries remain provisional playable content and should be evaluated later against this system. Current names, mechanics, and identities may be kept, revised, deleted, or expanded later.

---

# 1. Core Ontology

Luminae is about guiding cosmic society through technologies, affinities, and civilizational destiny.

The player is the **Architect**.

The core conceptual chain is:

```text
Affinities → Artifacts → Blueprints → Luminaries → Eminence
```

Where:

```text
Affinities = raw cosmic potentials
Artifacts = technologies that shape society
Blueprints = strategic/systemic modifiers and engines
Luminaries = civilizational endpoints or mythic destinies
Eminence = recognition of a society’s achieved cosmic direction
```

---

# 2. Affinities Are Survival Strategies

Affinities do **not** represent fixed species types.

They represent **civilizational survival instincts**: the fundamental way a society persists under cosmic pressure.

A biological species is not automatically Verdance. A machine species is not automatically Continuum. A hidden society is not automatically Abyss. The affinity depends on the civilization’s dominant strategy.

Core rule:

```text
Affinity color = survival philosophy, not species taxonomy.
```

---

# 3. The Five True Civilization Affinities

## Flare

**Color identity:** red-orange plasma  
**Survival instinct:** survive by ignition, expenditure, combustion, momentum, and decisive action.

Flare civilizations survive by burning hotter than the crisis around them.

They tend toward:

```text
reactors
propulsion
weapons
engines
war technologies
heroic sacrifice
fast expansion
catastrophic breakthroughs
```

Species/civilization examples:

```text
high-metabolism species
warrior cultures
rocket-age dynasties
reactor societies
predator expansionists
civilizations that act before stability exists
```

Core phrase:

```text
Flare = survive by burning.
```

---

## Verdance

**Color identity:** emerald / living green  
**Survival instinct:** survive by adaptation, growth, reproduction, healing, mutation, and symbiosis.

Verdance civilizations survive by becoming part of living systems or evolving with their environment.

They tend toward:

```text
biotech
terraforming
ecology
healing
regeneration
adaptive architecture
living machines
symbiotic societies
```

Species/civilization examples:

```text
protozoa-like intelligences
fungal networks
plant civilizations
adaptive swarms
primate-derived ecological societies
biosphere minds
regenerative cultures
```

Core phrase:

```text
Verdance = survive by growing.
```

---

Continuum civilizations survive by maintaining patterns across time.

They tend toward:

archives

long-lived species

Continuum = survive by enduring.

# 4. Singularity Is Not a Sixth Artifact Affinity

Singularity is **not** a normal civilization affinity.

It should not be treated as:

```text
a sixth artifact color
a normal civilization path
a standard Luminary path
a species category
```

Singularity is a **wildcard convergence force**.

It represents:

```text
compression
substitution
convergence
impossible possibility
wild resource flexibility
category collapse
temporary rule-bending
```

Core rule:

```text
Flare, Verdance, Continuum, Abyss, and Radiance are civilization affinities.
Singularity is a wildcard/convergence resource.
```

Singularity may visually relate to Encrypt because Encrypt compresses a possible Artifact pattern for later use, but this does not make Encrypt a Singularity Artifact mechanic.

Color identity:

```text
Singularity = prismatic white / chromatic lensing / unstable diamond-light.
```

---

# 5. Global Actions Are Not Affinities

Forge and Encrypt are global processes. They should not look like or mechanically imply specific affinities.

## Forge

**Meaning:** manifest possibility into a permanent Artifact.

Forge is not Radiance.

Visual language:

```text
dark cosmic metal
hammer icon retained
white-hot strike point
brief gold sparks
artifact-affinity glints
outward impact/manifestation
```

Core phrase:

```text
Forge = manifest possibility.
```

Forge should feel decisive and primary.

---

## Encrypt

**Meaning:** preserve an Artifact’s pattern for later.

Encrypt is not Abyss, not Continuum, and not a Singularity Artifact path.

Visual language:

```text
obsidian glass
prismatic white cipher aperture
chromatic edge fracture
inward folding/compression
sealed recoverable pattern
```

Core phrase:

```text
Encrypt = preserve compressed possibility.
```

Encrypt should feel elegant, strategic, and secondary-special. It should not visually overpower Forge.

---

# 6. Artifact Design Logic

Artifacts are technologies that shape cosmic society.

They should express one or more civilization affinities.

## Tier Logic

Recommended structure:

```text
Tier I = foundational single-affinity technologies
Tier II = hybrid two-affinity technologies
Tier III = civilization-defining multi-affinity technologies
```

This does not mean every Tier III must have exactly three colors, but Tier III should generally feel broader, more consequential, and more identity-defining than lower tiers.

Artifacts are not merely flavor. They are **breadcrumbs toward a civilization path**.

---

# 7. Luminary Design Logic

Luminaries are not just powerful cards.

They are the mythic endpoint, avatar, or destiny of a civilization’s path.

Current Luminaries remain provisional and should slot into this system. The system should not be warped merely to justify the current roster.

Core rule:

```text
Luminaries should conclude a strategy, not run the strategy.
```

Blueprints are the main system for ongoing strategic powers. Luminaries should not obsolete Blueprints.

---

# 8. Luminary Abilities and Ability Budget

Luminaries may have special abilities, but they should be carefully budgeted.

The purpose of a Luminary ability is to express identity, not to become the main engine of the game.

Recommended hierarchy:

```text
Artifacts = infrastructure
Blueprints = active strategic engines
Luminaries = destiny / endpoint / signature arrival
```

## Safe Luminary ability types

### Preferred

```text
Arrival effects
small one-time effects
narrow signature effects
identity markers
```

### Use cautiously

```text
small passive effects
conditional effects tied to the Luminary’s theme
```

### Avoid in core design

```text
large repeatable activated abilities
strong ongoing engines
effects that outperform Blueprints
```

## Requirement/Ability Relationship

A Luminary’s requirement should describe the civilization capable of summoning it.

A Luminary’s ability should describe what that civilization becomes when it arrives.

Example:

```text
The Void / mono-Abyss Luminary
```

If The Void has an **Oblivion** ability, its requirements should reflect Abyss survival logic: concealment, erasure, denial, hiddenness, or prior use of Oblivion-like effects.

But the ability should not become a dominant repeating engine unless the entire system is built around that risk.

---

# 9. Luminary Requirements

Luminary requirements should be more than color totals when special abilities are involved.

Recommended template:

```text
Luminary Requirement =
Affinity/Eminence threshold
+ behavior gate matching its survival philosophy
+ optional keystone artifact/tag for complex Luminaries
```

Examples of behavior gates:

| Affinity | Behavior gate examples |
|---|---|
| Flare | burst forging, high-cost artifacts, sacrificed tempo, rapid expansion |
| Verdance | growth chains, recovery, many artifacts, regeneration, discounts |
| Continuum | delayed value, reserve/encrypt use, sequencing, recurrence |
| Abyss | concealment, encryption, denial, erasure, Oblivion |
| Radiance | revelation, public thresholds, visibility, coordination, beacons |

Requirements should reinforce the Luminary’s fantasy without overcomplicating the base game.

---

# 10. Blueprints Must Remain Important

Blueprints should not be replaced by Luminary powers.

Blueprints are where the player should find:

```text
ongoing modifiers
strategic engines
resource conversion
action upgrades
alternative scoring routes
combo frameworks
```

Luminaries should be more like:

```text
identity unlocks
endpoints
arrival moments
victory-facing destiny markers
```

Critical rule:

```text
If a Luminary ability feels like a better Blueprint, weaken the Luminary or move the effect to a Blueprint.
```

---

# 11. Species and Civilization Mapping

Affinity combinations generate families of possible civilizations.

They should not create rigid species taxonomy.

Correct:

```text
Verdance + Abyss = hidden adaptive life
```

Incorrect:

```text
Verdance + Abyss = always fungi
```

A combo should be interpreted as a broad design prompt.

## Grammar

```text
Primary affinity = what survives
Secondary affinity = how it survives
Tertiary affinity = what it becomes under pressure
```

Example:

```text
Verdance + Abyss + Continuum
```

Means:

```text
Life survives through concealment and deep memory.
```

Possible expressions:

```text
fungal elder networks
buried root minds
cryptobiotic planetary ecologies
deep-ocean memory organisms
dormant extinction-cycle species
```

---

# 12. One-, Two-, and Three-Color Luminaries

Luminaries do not all need to be three-color.

A healthy roster may include:

```text
mono-affinity Luminaries
two-affinity hybrid Luminaries
three-affinity complex Luminaries
```

## Mono-affinity Luminaries

Represent pure survival philosophies taken to mythic extremes.

Examples:

```text
mono-Flare = ultimate ignition / overdrive / sacrifice
mono-Verdance = ultimate growth / bloom / regeneration
mono-Continuum = ultimate memory / recurrence / eternity
mono-Abyss = ultimate concealment / oblivion / void survival
mono-Radiance = ultimate revelation / law / beaconhood
```

## Two-affinity Luminaries

Represent major hybrid civilization strategies.

Example:

```text
Verdance + Abyss = hidden biospheres, parasitic priesthoods, fungal underworlds
```

## Three-affinity Luminaries

Represent complex civilization destinies.

Example:

```text
Flare + Radiance + Continuum = eternal crusader dynasties / solar law across eras
```

The roster should be curated for clarity and gameplay, not forced to exhaust all combinations.

---

# 13. Roster Policy

Current Luminaries remain in the game as provisional content.

They should later be reviewed and sorted into one of four buckets:

```text
Keep
Retheme
Rebalance
Replace
```

But this document does not require immediate Luminary deletion or renaming.

Core rule:

```text
Luminaries should slot into the system.
The system should not be warped to justify existing Luminaries.
```

# 14. Palette Lock

Recommended color identities:

| Element | Color / material identity |
|---|---|
| Flare | red-orange plasma |
| Verdance | emerald / living green |
| Continuum | deep blue / cyan flow |
| Abyss | black-violet / void purple |
| Radiance | solar gold / sacred white-gold |
| Singularity | prismatic white / chromatic lens |
| Forge action | dark metal + white-hot hammer strike |
| Encrypt action | obsidian glass + prismatic compression |
| UI trim | antique brass / muted cosmic gold, distinct from Radiance |

Important distinction:

```text
Radiance = sacred solar gold.
UI trim = muted antique brass.
Forge = dark hammer + white-hot strike, not Radiance.
Encrypt = obsidian-prismatic compression, not Abyss or Continuum.
```

---

# 15. What Not To Do

Do not make Singularity a normal Artifact color in the core system.

Do not make Singularity Luminary paths unless the core system is intentionally redesigned around Singularity Artifacts.

Do not let Encrypt become visually purple-dominant.

Do not let Forge become visually Radiance-dominant.

Do not make Luminary abilities so powerful that Blueprints become irrelevant.

Do not force all Luminaries to be three-color.

Do not make affinity combinations rigid species categories.

Do not redesign current Luminaries immediately just because this grammar exists.

---

# 16. Summary

The clean system is:

```text
Flare = burn
Verdance = grow
Continuum = endure
Abyss = conceal
Radiance = reveal
Singularity = converge

Forge = manifest possibility
Encrypt = preserve compressed possibility

Artifacts = technologies
Blueprints = engines
Luminaries = destinies
Eminence = recognition
```

This grammar should guide future redesigns of cards, UI, animations, lore, tutorial language, and expansion planning.
