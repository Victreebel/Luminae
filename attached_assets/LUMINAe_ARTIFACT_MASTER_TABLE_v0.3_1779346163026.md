# LUMINAe_ARTIFACT_MASTER_TABLE_v0.3.md

## Status

Draft source-of-truth candidate. This v0.3 does **not** change mechanics. It updates the v0.2 Artifact Master Table with civilization/species-family metadata after removal of the deleted Annihilation reference source.

## What v0.3 Changes

- Preserves Artifact ID, tier, affinity, cost, Eminence, and existing mechanics.
- Adds **Civilization / Species Lane** metadata.
- Adds **Combo Grammar** based on the active System Grammar and Species/Civilization Grammar.
- Adds **Artifact Family** and **Luminary Implication** fields.
- Removes pressure to justify cards through external annihilation/antimatter tech-tree coverage.
- Flags the minority of names that still read as events or Luminaries rather than buildable Artifacts.

## Core v0.3 Rule

```text
Artifacts are civilization breadcrumbs.
They should imply what kind of society/species is forming, not merely which advanced tech-tree node has been covered.
```

## Reaudit Summary

The roster remains fundamentally usable. The strongest improvement is metadata, not mass replacement. Cards tied to antimatter, containment, horizon engineering, or dimensional collapse may stay when they fit Luminae internally; they are no longer mandatory because of the deleted source.

1. Do **not** implement all renames immediately. Use this table first as metadata and design guidance.
2. Prioritize adding hidden/internal metadata fields before changing visible card names.
3. If a card name reads as an event, add art/lore that makes it visibly a device, relic, engine, vault, array, protocol, or substrate.
4. If a card name reads as a Luminary/entity, either rename it or frame it explicitly as non-sentient infrastructure.
5. Do not add Singularity Artifacts. Singularity remains a wildcard/convergence resource, not a sixth Artifact path.
